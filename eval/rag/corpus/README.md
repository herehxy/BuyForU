# RAG 评测语料

这三篇文档是**评测语料，不是生产语料**（`docs/FILE_INDEX.md` 对 `eval/rag/golden-set.json` 有同样的说明）。

## 目的

验证 RAG 链路是否通电、以及生产阈值 `0.65` 是否可达。检索参数见
`SpringAiPlanningModel`：`knowledge.retrieve(request, 5, 0.65)`。

## 硬性要求：文档里的数字必须与代码和数据库一致

RAG 只是**解释层**，规则的唯一真相源在下面这些地方。文档是第二份人手维护的副本，
天然有漂移风险，所以改任何一个数字前先核对来源：

| 规则 | 唯一真相源 |
| --- | --- |
| 满 5000 减 200 | `commerce_schema.promotion_rule`，种子在 `V6__pricing_rules_and_address_identity.sql`（`FULL_5000_200`） |
| 满 99 包邮、否则 10 元运费 | `commerce_schema.shipping_rule`（`STANDARD`，99.00 / 10.00） |
| 报价有效期 5 分钟 | `JdbcCommerceEngine` 的 `QUOTE_TTL` |
| 预占时长 15 分钟 | `JdbcCommerceEngine` 的 `RESERVATION_TTL` |
| 应付合计 = 商品金额 − 优惠 + 运费 | `JdbcCommerceEngine.pricing()` |

**如果这里的数字和上面任何一处不一致，RAG 就是在用错误的数字回答用户，而订单仍按真实规则成交——这是必须避免的缺陷。** 长期收敛方向是让这份文档由引擎配置派生生成，而不是人手维护。

## 写法要求

- 用**书面语**（"自签收次日起七个自然日内"），而 `golden-set.json` 里的 query 用**口语**（"我买的东西不想要了，最晚几天内能退"）。刻意制造词汇差异，才能验证是语义召回在起作用，而不是关键词命中。
- 单段落不超过 **1200 字符**（`PgVectorKnowledgeStore.chunk` 的切块上限），否则会被硬切。
- 用空行分隔段落，切块按段落边界进行。

## 金标集结构（v2）

`golden-set.json` 顶层是对象，不再是裸数组：

| 字段 | 含义 |
| --- | --- |
| `corpusDir` | 语料目录（相对金标集）。**语料清单不在这里维护**，由目录推导，避免第二份副本漂移 |
| `retrieval.topK` / `retrieval.threshold` | 必须等于 `SpringAiPlanningModel` 里的字面量 |
| `samples[].kind` | `positive`（应有命中）或 `negative`（不应命中） |
| `samples[].expectedDocumentIds` | 文件名去掉 `.md` 后的逻辑 id；负样本必须为空 |
| `samples[].minHits` / `maxHits` | 正样本用 `minHits≥1`，负样本用 `maxHits:0` |

配套的 `RagRetrievalEvalTest`（纯 JVM，不连库）守三件事：格式合法性、语料文档全覆盖、
以及 `topK`/`threshold` 与生产调用点一致。第三条是**防漂移**断言——改了生产阈值却忘了改金标集，
评测会在错误阈值下静默"通过"，比直接失败更危险。

新增一篇语料文档后，必须同时给它加至少一条正样本，否则测试会报出"未被评测的文档"。

## 阈值标定（2026-09-21）

生产阈值不是拍脑袋定的常数，而是由这份语料 + 金标集标定出来的：

| 项 | 数值 |
| --- | --- |
| 原阈值 | 0.65 |
| 实测相似度天花板（`embeddinggemma` + 整篇切块） | ≈ **0.62** |
| 原阈值的后果 | `retrieve()` 对**任何**查询都返回空——RAG 接好了线却永远是死的，且不报错 |
| 扫描出的安全窗口 | **[0.515, 0.535]**：下界由负样本最高分 0.5130 卡住，上界由最弱正样本 0.5365 卡住 |
| 现行取值 | **0.53**（取窗口上界，偏向精确率：召回错误的政策数字比不召回更危险） |
| 该取值下的表现 | 正样本召回 4/6，负样本误召 0/2 |

**这个标定只基于 8 条样本，属于初步值。** 扩样本、换嵌入模型、改切块粒度都必须重标——分数分布会整体平移，旧阈值直接失效。跨粒度尤其不可比：段落级切块会把所有分数一起抬高（正样本 0.749~0.891，负样本也升到 0.847）。

标定过程由 `RagRetrievalEvalIT` 固化：每次都从干净容器库重灌语料、跑真实嵌入，并把完整相似度矩阵打到测试输出里。其中 `thresholdIsReachable` 一条专门防"召回恒为空"复发——这条断言的存在本身就记录了上面那次事故。

## 已知的样本设计缺陷（待修）

现有两条负样本（"怎么改收货地址""能不能开专票"）对退换货/运费语料而言属于**邻域问题而非领域外问题**，测的是邻域区分力，不是"该不该召回"。要标定阈值下界，需要补真正与语料无关的问题。样本量也不足以给出可信阈值。
